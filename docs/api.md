# Platform API

Base URL for local development: `http://127.0.0.1:8080`.
The complete machine-readable contract is [openapi.yaml](openapi.yaml).
An ad is a catalog entry. Searches, actual exposures, clicks, feature snapshots,
and models have separate identities and lifecycles.

## Ranking and data endpoints

All `/api/v1/admin/**` routes and `/actuator/prometheus` require
`X-Admin-Token`, matching an `ADMIN_TOKEN` of at least 32 characters. They are
disabled when no suitable token is configured. This shared development token
does not provide tenant isolation or authenticate the end users of public routes.

| Method and path | Purpose |
| --- | --- |
| `POST /api/v1/search` | Retrieve and rank up to 50 ads; persist returned positions, features and model identity |
| `POST /api/v1/events/impressions` | Record that a returned ad was actually shown |
| `POST /api/v1/events/clicks` | Attribute a click to an accepted impression |
| `GET /api/v1/admin/metrics/ctr` | Mature per-ad impression and clicked-impression counts |
| `GET /api/v1/admin/metrics/model-quality` | Delayed log loss and Brier score for model-served impressions |
| `GET /api/v1/admin/training-data` | Inspect live mature examples with UUID keyset pagination |
| `POST /api/v1/admin/training-exports` | Freeze a bounded, consistent training dataset |
| `GET /api/v1/admin/training-exports/{id}` | Page through that immutable export |
| `POST /api/v1/admin/features/snapshots` | Publish an immutable, atomic set of per-ad counts |
| `GET /api/v1/admin/features/latest` | Read metadata for the latest compatible snapshot |
| `POST /api/v1/admin/models` | Register a model, preprocessing and evaluation evidence |
| `GET /api/v1/admin/models` | List up to 100 registered versions |
| `GET /api/v1/admin/models/{version}` | Retrieve the immutable artifact |
| `GET /api/v1/admin/deployment` | Read the active model, rollout percentage and revision |
| `PUT /api/v1/admin/deployment` | Compare-and-set rollout or rollback using the expected revision |
| `GET /api/v1/admin/deployment/history` | Inspect the last 100 deployment changes |
| `POST /api/v1/admin/experiments` | Create a fixed allocation and pinned treatment model |
| `GET /api/v1/admin/experiments/{id}/report` | Report mature assigned-user conversion and uncertainty |
| `POST /api/v1/admin/experiments/{id}/stop` | Stop enrollment and serving for an experiment; preserve its records |

### Search and attribution

```json
{"query":"camera","userId":"opaque-user-42","limit":10}
```

Add `"experimentId":"camera-ranking-v1"` to request a configured experiment.
The response includes `requestId`, `createdAt`, policy, model/snapshot identifiers,
assignment, fallback reason and ranked `items`. A returned item is not counted as
an impression. After display, submit:

```json
{
  "id":"c0e95891-a68c-4353-8ef6-bfe258e7d217",
  "requestId":"<requestId returned by search>",
  "adId":"<adId returned in items>",
  "occurredAt":"<actual display timestamp in UTC>"
}
```

The angle-bracket values above are placeholders, not valid event values. A click
has `id`, `impressionId`, and `occurredAt`. New events may arrive at most one hour
late. Exposure must occur within one hour of search; a click must occur within
24 hours of exposure. Identical event retries return `200` after an initial
`201`; conflicting identities or payloads return `409`. Multiple clicks do not
multiply the positive impression label. See [data-contracts.md](data-contracts.md)
for interval boundaries, receipt cutoffs and the 25-hour label maturity rule.

### Administrative writes

Feature snapshot, model, experiment and export creation use immutable identifiers:
same identity/content returns `200`, first creation `201`, different content `409`.
Models must include every field in the artifact schema, including evaluation
metrics. Use the artifacts generated by [the Java pipeline](ml-workflow.md).

Deployment changes send the revision read from `GET /api/v1/admin/deployment`:

```json
{"revision":0,"modelVersion":"camera-ranker-v1","rolloutPercent":10}
```

Successful changes increment the revision. A concurrent update returns `409`;
read the new state before deciding whether to retry. Setting `modelVersion` to
`null` with `rolloutPercent: 0` selects the baseline. A model that fails the
validation quality gate returns `422`. Stopping an experiment is idempotent and
routes its subsequent requests to baseline; global deployment changes do not
alter a running experiment's pinned model.

Metric endpoints accept `from`, `to`, and `asOf` UTC timestamps. Training export
creation accepts `id` (UUID) and `asOf`; reads use `limit` (1–5,000) and optional
`after` (UUID). For reproducible batch runs use frozen exports, not pages from
the live inspection endpoint. See [experiments.md](experiments.md) for report
interpretation and [ml-workflow.md](ml-workflow.md) for executable examples.

## Create an ad

`POST /api/v1/ads`, `Content-Type: application/json`

```json
{"title":"Camera","category":"Electronics"}
```

| Field | Contract |
| --- | --- |
| `title` | Required text, 1–200 Unicode code points in the submitted value |
| `category` | Required text, 1–64 Unicode code points in the submitted value |

Fields cannot be null, blank, or contain Unicode control characters. After
validation, surrounding whitespace is removed with Java `String.strip()`.
Case and interior spacing are preserved. Category is currently a free-form label,
not a reference to a managed taxonomy. No Unicode normalization such as NFC is
applied. Unknown JSON properties are rejected to surface misspelled fields.
Numbers and booleans are not coerced into text, and trailing JSON values are
rejected. A request must contain one JSON object matching the declared schema.

The server generates a UUID and UTC creation timestamp. Timestamps use
microsecond precision to match PostgreSQL, so create and read responses agree.

Successful response: `201 Created`, with
`Location: /api/v1/ads/<id>` and a body of this shape:

```json
{
  "id": "2834ebc2-dfa7-4af3-8e73-d130bb92f421",
  "title": "Camera",
  "category": "Electronics",
  "createdAt": "2026-09-21T10:00:00.123456Z"
}
```

The response is returned after the insert succeeds. PostgreSQL owns durability;
there is no application memory cache serving as the source of truth.

## Read an ad

`GET /api/v1/ads/{id}`

Returns `200` and the same representation for an existing UUID. A valid UUID
that does not exist returns `404`; an unparseable UUID returns `400`.

## Errors

Errors use `application/problem+json` with Problem Details fields. For example:

```json
{
  "type": "about:blank",
  "title": "Invalid request",
  "status": 400,
  "detail": "One or more fields are invalid.",
  "errors": [{"field":"title","message":"must not be blank"}]
}
```

Validation messages may vary with the validation provider and locale. Clients
should use the HTTP status and field names rather than matching message text.
Responses do not echo rejected values, SQL exceptions, credentials, or stacks.

| Status | Meaning |
| --- | --- |
| `400` | Invalid fields, unknown JSON properties, unreadable JSON, or invalid UUID |
| `403` | Administrative token absent, invalid, or disabled |
| `404` | Requested ad, model, export, snapshot, or experiment does not exist |
| `409` | Conflicting immutable write, missing attribution, or stale deployment revision |
| `422` | Model is ineligible for promotion or export exceeds the bounded size |
| `405` | Method is not supported for the route |
| `415` | Creation request has an unsupported content type |
| `503` | Database access failed or timed out |
| `500` | Unexpected server error; details remain in server logs |

## Retry and concurrency semantics

Catalog `GET` can be retried. Catalog `POST` is not idempotent: submitting the same body twice
creates two distinct ads. Duplicate titles are allowed because they are not
business identifiers. There is no check-then-insert race on title uniqueness.

A connection failure or timeout can leave a write outcome unknown, even if the
client receives an error. Do not blindly retry creation. A future idempotency
feature would require a durable request key and payload-consistency contract.
This API does not claim exactly-once creation.

Independent creates use separate database statements and UUID primary keys.
The application service is stateless and the repository uses Spring's JDBC
client with a bounded connection pool. A single insert uses PostgreSQL's
statement transaction; there is no multi-step transaction in this feature.

## Health and exposure

- `GET /actuator/health`: aggregate health.
- `GET /actuator/health/liveness`: application liveness, independent of the DB.
- `GET /actuator/health/readiness`: readiness state plus database connectivity.

Health details are hidden. A database outage is expected to make readiness fail
with `503`, while liveness stays `200` if the application is otherwise alive.

The application is configured for local use. End-user authentication, per-operator
authorization, tenant isolation, public ingress, and rate limits require a
separate deployment design before external exposure.
